Project: **@estebanforge/pi-antigravity-bridge**
Stack: **TypeScript / Node.js (ESNext / ES2022, ESM module)** targeting Node.js 22+, built as a streaming Gemini provider extension for `pi` (`@earendil-works/pi-coding-agent`) with TWO turn engines behind one contract: the default **ACP engine** (`src/acp/*`, `agy acp` over JSON-RPC stdio) and the fallback **stream-json engine** (persistent `agy` CLI process).

## STRUCTURE
*   `src/`: Core implementation modules
    *   `provider.ts`: Main `pi` custom provider: streaming event loop, G9 round-trip store (escalation-aware: slow bridge calls early-ack with a poll handle at ~20s — 120s for delegation-shaped tools, issue #6 — and re-arm to a 30 min TTL; failed parks leave tombstones for late-delivery re-routing), G1 context digest (on by default and self-gating; inline on stream-json under the ~25KB silent-drop budget, `embeddedContext` resource block on ACP), retry-drop resume turns (issue #8: a retry-dropped attempt with a bound conversation re-opens it with a synthetic resume prompt instead of the unretryable "no user message" error; the binding is written at the first park, not only on OK passes). Consumes the `TurnDriver` interface only; engine selection is per-call from config.
    *   `driver-types.ts`: Engine-agnostic `TurnDriver` contract (request/handle/snapshot types). Everything above the drivers depends on this only.
    *   `driver.ts`: Stream-json driver (fallback engine): one persistent `agy --input-format stream-json --output-format stream-json` process, turn serialization, recycle on profile drift, conversation binding, idle/abort timers (parks suspend both caps; the overall cap resumes its remaining budget on unpark, the idle cap re-arms a fresh window).
    *   `daily-log.ts`: Daily NDJSON support log (`<configRoot>/extensions-data/estebanforge/pi-antigravity-bridge/logs/<YYYY-MM-DD>.ndjson`, configRoot = dirname(getAgentDir())): error-only by default (zero routine disk writes; warns toast in the pi UI instead), full trail needs `AGY_DEBUG`, 14-day retention, secret redaction, never throws. Fed by both drivers, the bridge, round-trips, `/agy`, and `ask-tool`.
    *   `redact.ts`: `redactText()`: pattern-based secret scrubbing for free text (API-key prefixes, OAuth tokens, credential headers, token-ish JSON fields), word-boundary anchored, no internal length cap. Applied at reassembled-stderr boundaries (drivers, ACP connection, web tools, delegation exit note) and by daily-log value scanning; tokens split across pipe chunks still match because redaction sees the reassembled buffer.
    *   `acp/jsonrpc.ts`: NDJSON JSON-RPC 2.0 framing: correlation map, typed error results, server-to-client requests, line buffering (partial stdio frames).
    *   `acp/connection.ts`: ACP server process + protocol: initialize, session/new+load (bridge `mcpServers` on both), prompt with image/resource blocks, `set_config_option`, notification cancellation, private MCP-home isolation, parked permission answering (skip turns auto-allow; a wired human handler holds the JSON-RPC reply open under a 480s deny-by-default budget, `*_always` answers remembered per connection; every failure path fail-closes).
    *   `acp/events.ts`: `session/update` → DriverActivity mapping (pure). Tool frames: args unwrap `arguments` envelope, name from `_meta.mcp.tool`, `content[]` text/diff extraction. Load-replay suppression lives in the connection.
    *   `acp/driver.ts`: `AcpDriver`: serialized turns, park-paused caps (same semantics as stream-json: overall resumes its remaining budget, idle re-arms fresh), Gate D abort (notification cancel, 10s teardown fallback), connection-scoped exit handling, engine-scoped snapshots (reconnects, agentInfo).
    *   `native-tools.ts`: Stream-json only: maps agy read-only tool steps onto real pi builtins (`read`/`ls`/`grep`/`find`) for native re-execution. Not used on ACP turns (Gate C).
    *   `skills.ts`: `activate_skill` bridge exposing the pi Agent Skills catalog to agy, answered by the bridge directly.
    *   `bridge-catalog.ts`: The live bridge catalog: filters pi's tools per `tools/list` AND per `tools/call` by the active set, `bridgeTools` mode, session-only `/agy tools` hides, and the bridge's internal tools (AskAntigravity, antigravity, activate_skill, bridge_poll_result, agy_web_search/agy_read_url). A call outside the fresh set is rejected - a cached MCP catalog is not authorization.
    *   `web-tools.ts`: Opt-in web tools for any provider's model (`agy_web_search`, `agy_read_url`, default off via `config.webTools` / `AGY_WEB_TOOLS` / `/agy web`): each call spawns a one-shot search-only agy agent (`--mode plan`, `inheritMcp: false`, per-call agent dir under `~/.gemini/config/agents/pi-bridge-web-*`, removed in `finally`), enforces a 120s deadline + 2MiB cap, tolerates the OK/SUCCESS status drift, requires an observed native `search_web`/`read_url_content` step, and refuses any disallowed tool step; `sweepStaleWebAgents` at registration prunes dirs whose pid died (marker-less dirs after a 24h grace).
*   `approval-gate.ts`: Shadow tool factory (bash/write/edit) for the approval gate. Marker calls (`__agyGate`) are approval round-trips: ticket-verified, never executed locally; non-marker calls delegate to factory twins of the real builtins. Also maps agy native tool names onto the shadow surface.
*   `approval-detect.ts`: Third-party pi permission-extension detection (settings packages name-match + config markers) and `approvals.gateMode: auto` resolution (shadow only when a gate extension exists).
*   `approval-hook.ts`: Gate hooks staging into the session-private per-pid bridge dir (`bridgeMcpConfigDir()/.agents/hooks.json`, discovered via the extra `--add-dir` only this session's agy receives — issue #5 isolation), the legacy sweep for gate groups dead 1.6.x sessions left in shared workspace files, and the generated early-ack + poll hook script; staged timeout exceeds the park budget because hook timeouts soft-pass upstream.
*   `mcp-registration.ts`: Registers/unregisters the bridge in `~/.gemini/config/mcp_config.json` for the stream-json CLI (per-pid entries, atomic writes, stale sweep). Delegation isolation: `setBridgeEntriesDisabled` flips our entries off around `AskAntigravity` spawns; `acquireBridgeSuppression` refcounts overlapping delegations and records each delegator pid in a cross-process marker (`suppression.json`, liveness + 24h age pruned) so concurrent sessions and the marker-aware session-start heal (`healBridgeSuppression`) never re-enable entries while a live delegation is in flight; fresh registrations land disabled too.
    *   `discovery.ts`: Conversation-id binding for the AskAntigravity one-shot tool (snapshot/diff + pid fd-scan; `agy -p` never prints the id). Scheduled for deletion in phase 4.
    *   `ask-tool.ts`: The `AskAntigravity` one-shot delegation tool (model/thinking defaults, blocking + background runs with wake messages, `/agy-stop`). Always spawns `agy -p`, regardless of the configured turn engine; `mode: "plan"` keeps that path permanently (ACP has no review-only mode). Suppresses the bridge's global entries for the WHOLE delegated run, background included (agy watches the config and hot-reloads on file changes, so a mid-run re-enable pokes the live delegation; release fires on process close/error, exactly once per run).
    *   `config.ts`: Configuration defaults (engine, acp.usageEstimate, bridgeTools, askTool, webTools, digest, systemPrompt, skipPermissions), directory resolution, and environment parsing.
    *   `diff-render.ts`: `stream-json` only: git-sourced edit diffs into pi's thinking stream. `formatInlineDiff` (no git) renders ACP's native diffs. ACP edits arrive as diffs in `tool_call content[]`.
    *   `mcp-server.ts`: Internal bridge HTTP/MCP server lifecycle and capability gating; `tools/call` parks into the provider round-trip. Shared-secret `x-bridge-token`; handle exposes `token` for ACP `mcpServers` headers. Logs a `progress-token` probe when a request carries `_meta.progressToken`.
    *   `models.ts`: Antigravity model catalog loading and background cache refreshing; `toPiModel(entry, input)` advertises text+image input on both engines.
    *   `sessions.ts`: Persisted mapping of `pi` session IDs to agy conversation/session IDs. Engine-scoped KEYS (`sid:<x>` streaming, `sid:<x>@acp`) so engine switches never cross conversations.
    *   `sysprompt-agent.ts`: stream-json only: stages the G10 system prompt as a content-addressed agy agent file (one dir per distinct body, write-once, pid-marked, orphan-swept) under `AGY_AGENTS_ROOT` or `~/.gemini/config/agents`, passed via `--agent`. The carrier frontmatter declares the productive toolset explicitly (`tools:` - omission reads as a read-only default set upstream, issue #13, while agy appends the resource/MCP tools itself so G9 round-trips ride `call_mcp_tool` regardless) plus `subagent: false` + `agents: []`: agent-file presence already masks the native subagent tools (issue #7 probe), and the declaration makes it explicit. The prompt line never carries the block: the CLI silently drops single prompts past a ~25KB input cap (SUCCESS with an empty response, no error) and a conversation whose turn was dropped never responds again. A user-set `config.agent` wins, with an inline-block fallback and a one-time warning.
    *   `prompt-images.ts`: stream-json only: stages user-attached and redelivered image blocks to per-turn temp dirs (`pi-bridge-img-*` under the OS tmp dir, mode 0600, 24h stale sweep, fail-closed to a text-only turn) and builds the prompt note pointing the model at the paths; the pixels then arrive through the bridge read tool result (probe 2026-09-07: the CLI's MCP client delivers tool-result image content). ACP rides native `session/prompt` image blocks instead. Late/stranded redeliveries carry their images the same way (the redelivery prompt is text-only).
    *   `runtime.ts`: Realm-wide bridge runtime (`globalThis` brand-checked singleton) for multi-session pi processes: shared `SessionStore`, `options.sessionId`-routed `streamSimple` (refuses when multiple sessions are live and unmatched), one MCP listener with per-session route tokens (`addRoute`), and refcounted teardown of per-realm artifacts when the last session leaves.
    *   `engine-picker.ts`: First-run onboarding: `shouldOfferEnginePicker` (no config file + no `AGY_ENGINE`, fail-closed to false), `showEnginePicker` overlay (SelectList + DynamicBorder, stream-json preselected), `isAgyInstalled` (PATH scan with win32 `agy.exe` probing — Google ships only agy.exe there, and spawns are `shell: false`, so Node refuses `.cmd` shims — or explicit `AGY_BIN` path), `savedEngineMessage` / `agyMissingMessage` toast copy, `toEngine` value narrowing.
*   `extensions/`: `pi` extension entry point (`index.ts`): provider registration, dual-driver wiring, bridge `mcpServers` registration with the token header, the `/agy` command (engine, tools, web, bridge, mode, permissions, timeout, digest, system-prompt, ask, model, thinking, auth, auth-manual, doctor, clear), ACP-only native tool display events (entry renderer, `pi-bridge` self-filter, pending-tools status), the live `ACP ≈ in / out` usage status, engine-gated global MCP registration (now only the isolated-home fallback) with sweep/heal running on BOTH engines, first-run engine picker, confirmed `agy` installer flow, and managed legacy-binary cleanup in `session_start` (the retired `acp.bin` config key also auto-strips there; only a set `AGY_ACP_BIN` env var still warns).
*   `scripts/`: Utility scripts for development (`smoke-in-pi.sh`, `smoke-stream-json.mjs`, `smoke-acp.mjs`, `smoke-acp-bridge.mjs`, `smoke-acp-image.mjs`, `parity-live.mjs`, `probe-acp-phase2.mjs`, `test-provider.ts`, `test-extension.ts`).
*   `tests/`: Test suite run by Vitest. ACP suites: `acp-jsonrpc` (framing, frame ceiling, noise filter), `acp-events` (mapping incl. probe-frame regressions), `acp-driver` (fake server in `tests/helpers/fake-acp-server.mjs`), `acp-config` (engine narrowing). Bridge: `bridge-catalog` (active-set/mode/hidden filtering, internal-tool exclusion). Web tools: `web-tools` (answer gate, stale-agent sweep, URL/query validation; executable fixture `tests/helpers/fake-agy-web.mjs`). ## NOTES
*   **Two engines**: default `acp` (`agy acp`; requires agy 1.5.3+); `stream-json` (persistent `agy` CLI process) stays as the supported fallback. Both use the CLI's cached credentials. Both engines stage a private Gemini home that shares CLI state but filters all global per-pid bridge registrations: ACP via per-session `mcpServers`, stream-json via the probed top-level `--gemini_dir` flag (probe-refused or `AGY_AGENTS_ROOT` override falls back to legacy global registration plus suppression, issue #14). Startup offers the official CLI installer after confirmation and removes only marked builds from the retired managed ACP layout. Switch via `config.engine` / `AGY_ENGINE` / `/agy engine` (restart applies). Both implement `TurnDriver`; the provider layer (G1 digest, G10 system prompt, G9 round-trips) is shared - G10 delivery differs per engine: staged agent file on stream-json, inline block on ACP.
*   **First-run onboarding**: no `config.json` + no `AGY_ENGINE` + TUI = the engine picker modal at `session_start` (acp first, esc re-asks next start). A missing or too-old `agy` prompts before the official installer runs; afterwards the user authenticates with `agy` and restarts pi. Headless prints instructions only.
*   **Native ACP protocol**: agy 1.5.3 uses separate `model` and `thought_level` options, `default`/`accept-edits`/`plan` modes, exact PromptResponse.usage, and notification-based `session/cancel`. Estimates stay as a fallback when usage is absent. Provider plan turns remain refused; plan delegations keep `agy -p --mode plan`.
*   **PromptResponse.usage total is a billing sum, not context** (issue #12, probe-calibrated 2026-11-10): agy sums input+cacheRead+output over EVERY inference of the prompt (2 steps = ~2x the true occupancy; 18 steps gauged 107% at ~7% real and compaction destroyed the session). The driver keeps the billing fields but replaces `total_tokens` for pi's gauge with Σin + Σout + ceil(ΣcacheRead / (toolBatches + 1)) — toolBatches counts tool_call BATCHES (a batch opens on the first tool_call after model output and closes on the next output frame, so parallel calls and out-of-order completions are one batch), exact at one inference; the divisor can only shrink from miscounting, so every residual error over-reads, the safe direction. `usage_update` occupancy frames (the authoritative source) do NOT exist on native agy 1.5.4 (`AGY_ACP_LIVE=1 AGY_PROBE_DRIVER_ONLY=1 npx tsx scripts/probe-acp-usage.mjs` recalibrates); when a runtime sends them the driver uses them instead, mid-turn and at settle, and Gate B estimates keep the observed total too. Pi-side `calculateContextTokens` reads `Usage.totalTokens` as live context length, and its own fallback sums cacheRead too, so an uncorrected aggregate is never safe to emit. The provider additionally clamps the EMITTED usage (`clampOverflowUsage`, issue #20): pi-ai's `isContextOverflow` judges by `input + cacheRead` alone (Case 2, `stopReason "stop"`), so billing sums in those fields would trip a phantom pi-side compaction; when `totalTokens` fits the context window, the sums are proportionally rescaled into the single-turn budget (cache ratio kept; genuine overflows, driver billing fields, and cost always-zero untouched).
*   **Native display events (ACP-only)**: agy's own tool steps render as display-only pi cards (started/completed/failed with path, colored diff lines, command line, or output; persistence bounded at 4000/12000/500 chars). Events carrying `mcpServer: "pi-bridge"` or a per-pid bridge name are filtered out so bridge round-trips with genuine pi cards never double-render. Stream-json keeps its stronger native re-exec instead.
*   **ACP-only features**: the G1 digest ships as an `embeddedContext` resource block; edit diffs from `tool_call content[]` render in the thinking stream with no git subprocesses (native re-exec and wrapper replay are retired on ACP turns). Image attachments ride BOTH engines: ACP as typed `session/prompt` content blocks, stream-json staged to temp files (`prompt-images.ts`).
*   **Sessions**: engine-scoped keys (`sid:<x>` streaming, `sid:<x>@acp`) — engine switches never cross conversations and rollback preserves both bindings.
*   **Architecture**: The MCP tool bridge runs on upstream pi APIs: bridge calls park in the provider's round-trip store and re-enter pi as real `toolUse` turns (native cards, permissions, hooks). The pre-1.3.0 spawn-and-poll SQLite engine was removed in 1.3.2 (issue #1).
*   **Approval gate**: agy native tool calls (`run_command`, `create_file`, `edit_file`, ...) can be routed through a pi-side approval: `.agents/hooks.json` (staged in the session-private per-pid bridge add-dir, so ONLY this session's agy loads it) PreToolUse parks in `POST /approval`, the provider emits a shadow `bash`/`write`/`edit` toolUse (reusing the G9 round-trip), pi's permission extensions gate it, the decision rides back to the hook. Opt-in: `approvals.gateMode auto|shadow|dedicated|off` (default auto = off until a third-party gate extension is detected), `approvals.mode ask|allow|deny` fallback (headless deny). Marker calls never execute locally; `verifyTicket` denies forged markers. All paths deny fail-closed (timeout, unwired, close). Hook discovery and execution live-verified 2026-09-22 (stream-json probe, marker hook fired); the full park→shadow-tool→decision round-trip is not yet live-verified. ACP turns have native parity: `session/request_permission` parks on a dialog (`ctx.ui.select` under the dialog lock) with the turn budget paused, honoring the same `approvals.mode` semantics (allow = synchronous auto, deny/headless/esc = fail-closed) with per-connection `*_always` memory.
*   **Context Continuity**: The G1 context digest defaults ON and is self-gating (`config.digest` / `AGY_DIGEST` / `/agy digest on|off`): it ships only when the delta window is non-empty - a fresh conversation opened by a mid-session model switch or engine switch (fresh mode: own turns and tool results included, since agy's DB holds nothing), another provider's turns, pi-side tool runs, or an undelivered compaction summary - and each piece ships once (watermark + content-keyed `digestSummaryId` on the session record - index identity would swallow the second compaction, since pi puts every post-compaction summary at the transcript front; a boundary fingerprint `digestBoundary` resets to the full delta when the transcript mutated under the watermark, e.g. /tree or /fork; records written before the fingerprint existed keep their watermark). Pure antigravity sessions get an empty delta, byte-stable prompts, and an intact server-side prompt cache. On stream-json the digest is capped under the ~25KB single-prompt silent-drop budget (issue #2; per the 120k-char embeddedContext probe, the ACP engine cap is 24k chars - transport accepted it with exact extremity recall - while stream-json keeps its 8k inline clamp); delivery differs per engine (inline vs embeddedContext resource block). `session_compact` rotates the binding (issue #20): the summary ships into a FRESH agy conversation armed by a one-shot in-memory handoff latch that survives failed retries, and a post-compaction toolResult/assistant tail seeds that fresh conversation (`COMPACTION_RESUME_PROMPT` + `includeLast` digest) instead of the unretryable no-user-message error; pi's ephemeral helper calls (`cacheRetention "none"` summaries, `disableContinuation` replays) classify as ephemeral and never read or write the store. Latch limits: memory-only (a restart with the digest off starts a user-prompt-tailed session fresh - the tail rescue still applies), rotation fires regardless of active model (another provider's compaction also rotates; the digest rebuilds on return), and a rotation landing mid-park keeps the rotation (parked continuations and strand redeliveries into the old conversation decline to rebind). Watermark delivery invariant: the settle write may only claim what reached agy - a built digest dropped by the stream-json byte cap (multibyte over-reservation) HOLDS the watermark so the window re-offers next turn, while partial renders (newest-first budget cut old turns) still advance because the hole can never re-fit and re-offering would duplicate cap-sized blocks into agy's DB; every digest build logs a `digest` event (engine, bound, bytes, window, deliveredFrom, shipped; warn on drop, info otherwise, AGY_DEBUG-visible) as the cap-deciding telemetry. An ACP `session/load` failure that silently creates a fresh conversation no longer ships blind: the provider prebuilds an as-if-fresh `fallback` variant on every bound ACP turn request (system prompt gate open, full `bound: false` digest) and the driver swaps prompt+contextBlock at the load-failure point; stream-json cannot detect its stale-id drop, so the field is ACP-only and the post-turn recreation `store.delete` still re-binds at watermark 0 (one duplicated context turn, accepted for correctness).
*   **Quota exhaustion (issue #16)**: agy streams the account quota notice as agent text and ends the turn `end_turn`, so the provider reclassifies a text-only notice response into a retryable pi error (`src/quota-notice.ts`; turn-level guard: no tool or thinking activity, session binding untouched). The errorMessage wording must satisfy pi-ai's `isRetryableAssistantError` (retryable markers: `rate.?limit`, `ResourceExhausted`; fail-fast traps: `quota exceeded`, `billing`, `out of budget`) - never echo the raw notice. Detection is content-based; a structured upstream signal (probe on an exhausted account for `_meta`/stopReason/error codes) is still unknown.
*   **agy-native background tasks**: agy backgrounds shell work itself (`run_command` with `WaitMsBeforeAsync`) and its RPC never reports the task - a live probe (2026-11-09, `session/prompt` returning with a 45s background sleep running) confirmed zero post-turn `session/update` frames for 150s. The completion path back into pi is the filesystem watcher in `src/background-watch.ts`: turns with the background arg shape arm it at settled end, and quiescence (no `lsof` holder + no bytes/mtime change over 30s) fires an `agy-background-task` custom message. Never strengthen the wording to "finished": fd-hold proves a writer, not liveness, and a log unlinked while held reads idle. Armed/settled `pi.appendEntry("agy-background-watch")` records are the reload-survival contract; `rearmPlansFromEntries` is the only sanctioned way to wake from a sweep.
*   **Held-session reuse on ACP (issue #21)**: the connection remembers sessions it created or loaded and skips `session/load` for them - reloading restarts agy's update stream, and the old stream's completion signal can land after the next `session/prompt` and end it early with replayed history and zero usage (agy 1.5.13 race; the reporter logged 2 of 47 loads landing exactly on the broken turns). This reduces exposure, it does not fix agy. Consequences: MCP catalog changes reach a held session only on its next reload or an agy process restart (the `/agy bridge` toast points at `/reload`), and a failed prompt/model step on a QUIET reused session reloads once, re-applies config, and retries (`session-reload-retry`) because agy may have dropped it; a turn that already streamed output or parks settles ERROR instead, since a re-prompt would double side effects.
